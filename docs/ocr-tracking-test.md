# 카드 박스 추적 + 선 통과 시 1회 읽기 테스트

## 아이디어

Ultralytics 추적 예제에서 화면에 선을 긋고 사람이 몇 명 지나가는지 세는 방식(라인 카운팅)을 컨베이어 카드에 적용했다. 프레임마다 카드 박스를 찾고, 박스에 번호(ID)를 붙여 따라가다가, 카드가 읽기 선을 넘는 순간 그 카드만 잘라서 한 번 OCR을 돌린다. 이미 읽은 ID는 다시 읽지 않는다. 즉 하나 읽으면 지우고 다음 카드를 읽는 구조다.

## 구현

카드 검출은 학습 없이 처리했다. 어두운 배경 위의 밝은 카드라서, 화면 중간~아래 띠의 세로줄 밝기로 카드 열을 나누고 각 열에서 밝은 구간을 카드의 위아래로 잡는다. 위쪽 조명 반사 때문에 단순 윤곽선 검출로는 옆 카드끼리 붙어 버려서 이 방식을 택했다. COCO로 학습된 기본 YOLO 모델에는 카드나 종이 클래스가 없어서, YOLO를 쓰려면 카드 사진으로 따로 학습이 필요하다. 검출 함수(detect_cards)만 바꾸면 나머지는 그대로 쓸 수 있게 분리해 두었다.

추적(CardTracker)은 카드가 가로로 일정하게 흐르는 점을 이용해, 이전 프레임에서 가장 가까운 중심을 같은 카드로 이어 붙인다. 선을 넘은 뒤 8프레임 안에서 가장 선명한(흔들림이 적은) 장면을 골라 읽고, 혹시 ID가 바뀌어 같은 카드를 또 읽는 경우를 대비해 텍스트 중복 필터(Deduper)도 한 번 더 거친다. OCR 엔진은 비교 결과 가장 나았던 RapidOCR을 썼다.

## 결과

같은 세 영상(기본, 빠름, 저대비, 각 약 700프레임)으로 돌렸다.

읽기 선을 화면 가운데(0.5)에 두었을 때, 기본은 OCR 4번으로 지문 4개를 중복 없이 읽었고 CER은 16.0%였다. 저대비도 4번 읽어 4개, CER 10.1%였다. 빠름은 7번 읽어 5개를 맞췄고 2번은 흔들림 때문에 글자가 많이 깨졌다(CER 28.0%).

가운데에 조명 반사가 걸려 있어서 읽기 선을 화면 왼쪽 35% 위치로 옮기자 크게 좋아졌다. 기본은 4개를 중복 없이 CER 4.9%로 읽었고, 저대비는 5개를 CER 8.1%, 빠름은 8번 읽어 7개를 맞추고 CER 18.1%였다. 세 조건 모두 중복 읽기는 0이었다.

프레임 전체를 OCR에 넣는 기존 방식과 비교하면 차이가 크다. 같은 RapidOCR로 프레임 전체를 읽었을 때 CER은 기본 13.9%, 빠름 20.4%, 저대비 17.6%였고, 중복 필터를 거쳐도 중복이 수십 줄씩 새어 들어갔다. 추적 방식은 카드 한 장만 잘라 읽으니 옆 카드 글자가 섞이지 않아 정확도가 오르고, 카드당 한 번만 읽으니 중복이 구조적으로 생기지 않는다. OCR 호출도 영상 하나당 4~8번이라 계산량이 프레임 전체 방식보다 훨씬 적다.

## 한계와 다음 단계

첫째, 추적은 연속된 프레임이 필요하다. 지금 서버는 휴대폰에서 약 2초마다 한 장씩 받는데, 그 사이 카드가 많이 움직여 같은 카드로 이어 붙이기 어렵다. 실제 파이프라인에 넣으려면 전송 간격을 초당 5장 이상으로 줄이거나, 휴대폰 쪽에서 검출과 추적을 하고 선을 넘은 카드 사진만 서버로 보내는 구조가 필요하다. 후자가 전송량도 가장 적다.

둘째, 읽기 선 위치는 촬영 환경(반사 위치)에 따라 조절해야 한다. --line 옵션으로 바꿀 수 있다.

셋째, 카드 검출은 이 송출기 화면(어두운 배경, 밝은 카드)에 맞춘 방식이다. 배경이 바뀌는 환경이라면 카드 이미지로 YOLO를 학습시켜 detect_cards를 교체하고, 추적도 Ultralytics의 model.track(persist=True)로 바꾸는 것을 검토할 수 있다.

재현 방법: python ocr_bench.py truth 후 python ocr_bench.py track basic.mp4 fast.mp4 lowcontrast.mp4 --line 0.35
